# ねこねこゲーム（プロトタイプ）

猫を容器にぎゅうぎゅう詰め込む、物理挙動を使った落ちゲーのプロトタイプです。
猫を容器に落とすと、ほかの猫や容器に押されて **猫の形を残したまま「むにっ」と変形** し、隙間に収まります。

> 現在のステータス: **Phase 1〜12 まで実装済み**（むにむに感、手でつまんで落とす、5色（白・黒・茶トラ・サバトラ・三毛）、同色4匹の消去と「にゃー！」→ジャンプの退出演出）。連鎖（CHAIN表示・連鎖ボーナス）とゲームオーバーまで実装済みです。Phase 12 では、スマホでの誤操作防止・自動画質調整・BGM と効果音を入れました（スマホ実機での確認待ち）。進捗は [TODO.md](./TODO.md) を参照してください。

## 遊び方

0. タイトル画面で「スタート」を押します。
1. 画面上の手が、次の猫の首根っこをつまんで運んできます。
2. 画面を押したまま左右に動かして位置を決め、離すと猫が落ちます。
3. 同じ色の猫が **4匹以上くっつく** と、少し間を置いて「にゃー！」と鳴き、自分でジャンプして容器から出ていきます（1匹100点）。
4. 空いたすき間に上の猫が落ちて、また4匹そろえば **連鎖** です。揃った場所に「2 CHAIN!」と表示され、得点は「1匹100点 × 連鎖数」になります。
5. 猫が容器上部の点線（ゲームオーバーライン）を越えて積み上がり、そのまま 1.5 秒たつと **GAME OVER** です。危なくなると、ラインが赤く点滅して「あぶない！」と出ます。Restart で最初から、「タイトルへ」でタイトル画面に戻れます。

## 起動方法

```bash
npm install
npm run dev        # http://localhost:5173/ （--host 付きなので同じLANのスマホからも開ける）
npm run build      # 型チェック + dist/nekoneko/ へビルド
npm run deploy     # ビルドして Cloudflare Workers へデプロイ
```

## 告知動画

`promo/nekoneko-promo.mp4`（縦 1080×1920 / 30fps / 約29秒 / H.264 + AAC、音量は -14 LUFS にそろえている）と、表紙画像 `promo/nekoneko-promo-cover.jpg` です。

作り直すときは、開発サーバを起動した状態で `npm run promo` を実行します。出力先は `promo/`（Git の管理外）で、環境変数 `PROMO_OUT_DIR` を指定すると別の場所に出せます。動画そのものはリポジトリとは別に管理します。

- `tools/promo/scenario.js`: 台本です。ゲームの開発用フック（`window.__game`）でゲームを1コマずつ進め、字幕や効果文字を重ねます。字幕は時刻で決め打ちせず、ゲームの出来事（着地・4匹揃った・にゃー・連鎖・ゲームオーバー）に合わせて出します。乱数は固定しているので、毎回同じ動画になります。
- `tools/promo/record.mjs`: インストール済みの Chrome をヘッドレスで動かして1コマずつ撮影し、ゲーム中に鳴った音を書き出して（`renderRecordedAudio`）、ffmpeg（`ffmpeg-static`）で MP4 にまとめます。
- ショート動画アプリは、画面の下と右にボタンや説明文が重なります。そのため、ゲーム画面は少し小さく上寄りに置き、字幕は中央付近に出しています。

## 操作方法

| 操作 | 内容 |
| --- | --- |
| 画面をタッチ / マウスを押す | 猫の首根っこをつまんだ手が、その横位置へ移動 |
| そのままドラッグ | 左右に位置を調整（手が少し遅れて付いてくるので、猫がぶらんと揺れる） |

## 技術構成

- **TypeScript + Vite**
- **Canvas 2D** で描画
- **自作の擬似Soft Body（Position Based Dynamics + Shape Matching）**。外部の物理エンジンは使っていません

### 技術方針とその理由

| 候補 | 判断 |
| --- | --- |
| Three.js | 見た目は2Dのデフォルメ猫なので、3Dのレンダラは不要。Canvas 2Dのパス描画のほうが、変形する輪郭を滑らかに描きやすい |
| Rapier / Matter.js などの剛体エンジン | 剛体を関節でつなぐ方式は、「面積を保ったまま潰れて横に広がる」表現が難しく、関節が多いと不安定になりやすい。猫1匹あたり30点程度の点群を独自に解くほうが、調整も挙動も扱いやすい |
| 流体 / Metaball | 猫がスライム化する。今回の要件（最後まで猫に見える）と逆方向 |
| **PBD + Shape Matching（採用）** | ブラウザ上で安定・高速（無条件に安定しやすい）。「形状へ戻る力」「面積保存」「伸縮の上限」を別々の拘束として持てるので、「猫らしさ」と「柔らかさ」を独立に調整できる |

## Soft Body表現の仕組み

猫1匹は次の要素で構成されます（`src/cat.ts`）。

```
       ／＼＿／＼        頭リング（10点）… 強い剛体Shape Matchingで形を保つ → 顔・耳は崩れない
      （  ・ω・ ）
  ～～（          ）     胴体リング（20点）… 変形の主役
   尻尾 ＼＿＿＿＿／      尻尾（7点）… 見た目用の紐。衝突なしで揺れる
```

各サブステップで、以下の拘束を順に解きます。

1. **全身Shape Matching**（`stiffness`）
   猫全体の点群から「最もよく合う回転 + 面積を保った伸縮」を求め、静止形状をその変形で置いた位置へ引き戻します。
   伸縮は `deformation` でどれだけ許すかを決め、`maxStretch` で上限をかけます。
   → 上から押されると「平べったい猫」、隙間に挟まると「細長い猫」になります。ただし猫のシルエットからは外れません。
2. **頭の剛体Shape Matching**（`headStiffness`）
   頭は回転と平行移動だけを許し、形は保ちます。顔・耳はこの変換で描くため、胴体が大きく変形しても猫と認識できます。
3. **輪郭の辺長レンジ拘束**（`edgeStiffness`, `edgeMin`, `edgeMax`）
   隣り合う点の距離を一定範囲に保ちます。伸びはしますが千切れません。
4. **首の拘束** … 頭と胴をつなぎます。
5. **面積保存**（`volume`, `compressibility`）
   胴体の面積（2Dでの体積）を保ちます。上から潰されると横へ逃げます。周りから押されているときだけ、`compressibility` の割合まで一時的に縮みます（「ぎゅっ」）。

衝突（`src/world.ts`）:

- **猫 vs 猫**: 一方の物理点が、もう一方の胴体 / 頭ポリゴンの内側に入ったら、最も近い辺へ押し出します（点と辺の両方を質量比で動かします）。頭と胴が重なる内側の辺は押し出し先から外し、押し出しが往復する現象を防いでいます。
- **猫 vs 容器**: 容器は太さのある線分（カプセル）の集合です。前のサブステップでいた側へ押し戻すので、すり抜けにくくなっています。
- **摩擦** は位置ベースのクーロン摩擦です。押し付けられている量（めり込みの解消量）に比例した分だけ、接線方向の移動を打ち消します。山の上でずるずる滑り続けず、軽く触れただけの壁に貼り付くこともありません。
- **めり込みの解消** は、1サブステップあたりの押し出し量に上限を設けています（`MAX_PUSH`）。また、深いめり込みの解消分は速度に変換しません（`FREE_DEPTH`）。猫が重なって出現しても、弾け飛ばないようにするためです。
- **容器の壁** は、点ごとではなく猫の重心がいる側へ、猫全体を押し出します。縁に乗った猫が壁をまたいだまま止まらないようにするためです。
- **立ち直り反射**（`Cat.applyRighting`）: 猫は必ず足から着地します。何にも触れていない空中では、重心まわりの回転速度を「直立へ戻る回転速度」へ近づけます。重心の落下には影響せず、形は内部拘束が保つので、体をひねって回るように見えます。着地してから `landRollTime` の間は弱く起き上がろうとし、山に埋もれた猫には働きません（むにむに感を壊さないため）。落下中は足を下へ伸ばして着地に備えます（`Cat.reach`）。
- **減衰** は、重心の動きにかかる `damping` と、猫内部の揺れだけにかかる `internalDamping` / `packedDamping` に分けています。単独の猫は着地で「ぷるん」と揺れ、山の中の猫は早く落ち着きます。

つままれている猫（`src/hand.ts`, `World.hold / release`）:

- 首根っこ（頭リングの後ろ側の1点）だけを手の位置に固定し、残りは普通に物理で動かします。そのため、手を動かすと振り子のように揺れます。
- つままれている間は、静止形状を「ぶら下がりポーズ」へブレンドします。このポーズは、首根っこの真下に縦長の胴体が垂れた形で、面積は香箱座りと同じです。重心が首根っこの真下に来るように作ってあるので、吊っても傾きません。離すと0.6秒かけて香箱座りに戻ります。
- 手足は重力方向へだらんと垂れ、猫の横の動きと逆向きに少し遅れて揺れます。脚の長さはポーズのブレンド率に比例するので、離すと縮んで、香箱座りの足先に戻ります。
- 指の間には、引っぱられた首の皮を描いています。
- 他の猫や容器とは衝突しません。離した瞬間にワールドへ加わります。横方向の勢いは `releaseSwing` の割合だけ残ります。

消去ルール（`src/rules.ts`）:

- グリッドは使わず、猫の形どうしの距離でつながりを判定します。同じ色の2匹について、一方の点（胴体・頭の物理点に、耳の先と中ほどを加えたもの）が、もう一方の胴体・頭の輪郭から `matchMargin`（3px）以内にあれば「つながっている」とみなします。見た目でぴったり触れているくらいです。
  - 耳は当たり判定を持ちませんが、見た目で触れているのがわかりやすいので含めています。尻尾は、乗っているだけでつながると甘すぎるため、既定では含めません（`matchUseTail`）。
- 着地直後は判定しません。猫ごとに「止まっている時間」（`restTime`：全身の点の平均の速さが `settleSpeed` 未満の時間）を数え、つながっている全員が `matchSettleTime` 秒以上止まってから判定します。1匹でもまだ転がっていれば、そのグループは待ちます。
- `matchContactTime` 秒以上つながり続けたペア（`World.stablePairs`）を、Union-Find でつなぎます。`matchCount` 匹以上の連結成分がそろったら消去の対象です。一瞬離れても、継続時間はすぐにはゼロに戻りません。
- Debug表示では、同色のつながりを金色の線で描きます（点線＝つながり始め、太線＝判定に数えられている）。
- 演出の流れ:
  1. ready（`exitReadyTime`）: 光って「！」が出て、目がまんまるになります。形の復元力（`stiffBoost`）が上がり、元の猫らしい形へぎゅっと戻ります。
  2. meow（`exitMeowTime`）: にっこり顔で「にゃー！」の吹き出しを出し、鳴き声を鳴らします。
  3. jump: 他の猫・容器と衝突しない状態（`ghost`）になります。近い方の縁を越える放物線でジャンプして容器の外へ出ていき、画面外で削除されます。
- 連鎖:
  - 猫が出ていった結果（上の猫が落ちてきて）新しく揃ったら、連鎖 +1 です。
  - 前のグループが揃ったあとにプレイヤーが落とした猫を含むグループは、連鎖ではなく1からやり直します（`Cat.releasedAt`）。演出中に次の猫を落としても、連鎖が水増しされないようにするためです。
  - 同じフレームで同時に揃ったグループは、同じ連鎖段数です。
  - 最後に猫が出ていってから `chainWindow` 秒、新しく揃わなければ連鎖は終わりです。
  - 得点は「匹数 × 100 × 連鎖数」です。2連鎖以上では、揃った場所に「N CHAIN!」、上部の CHAIN 欄に現在の連鎖数が弾むように出ます。鳴き声は連鎖が進むほど少し高くなります。
- 鳴き声とジャンプ音は Web Audio で合成しています（`src/audio.ts`）。ブラウザの制限で、最初に画面をタップするまでは鳴りません。

タイトル画面（`index.html` の `#title`、`main.ts` の `gameState`）:

- ゲームの状態は `title`（タイトル）→ `play`（プレイ中）→ `over`（ゲームオーバー）です。
- ロゴはシンプルに、「ねこねこ」を茶色の縁取りの白い丸文字で大きく、その下に「ゲーム」を小さく置いています。ときどき「むにっ」と弾みます。フォントは M PLUS Rounded 1c（Google Fonts）で、読み込めないときは丸ゴシックで表示します。
- タイトル中は背景の容器にときどき猫が落ちてくるデモを流します（最大14匹）。デモでは、得点・鳴き声・ゲームオーバー判定は動きません。
- ベストスコアと、遊び方を2行で表示します。
- 文字サイズはゲーム画面の幅（`cqw`）を基準にしているので、画面の大きさが変わっても同じ見た目になります。

ゲームオーバー（`src/gameover.ts`）:

- 猫の胴体の物理点のうち `gameOverRatio`（半分）以上がラインより上にあり、何かの上に乗って、ゆっくりとしか動いていない（平均の速さが `gameOverSpeed` 未満）。この状態が `gameOverTime` 秒続いたらゲームオーバーです（猫ごとの `overTime`）。
  - 飛んでいる・跳ねている最中は、`overTime` をゆっくり減らします。物理挙動による一瞬の飛び出しでは負けません。
  - 「止まっている」の基準は、消去判定（`settleSpeed`）より緩くしています。次々に猫を落としていると、山が押されて揺れ続け、ラインを大きく越えてもゲームオーバーにならなかったためです。
  - 揃った猫が出ていく演出中は、カウントを止めます。空きができて下がれば助かるからです。
- 危険度（一番危ない猫の `overTime / gameOverTime`）に応じて、ラインの点滅が速くなります。15% を超えると「あぶない！」と表示します。ラインと文字は、容器の中の猫より手前に描きます。
- ゲームオーバー画面には、スコアとベストスコア（`localStorage` に保存。保存できない環境では無視）を出します。新記録なら「NEW RECORD!」を出します。Restart で最初からやり直せ、「タイトルへ」でタイトル画面に戻れます。

音（`src/audio.ts`）:

- 音声ファイルは使わず、すべて Web Audio で合成しています。音量は `VOL`（master / bgm / sfx）で調整します。
- ブラウザの自動再生制限があるため、最初のタップ/クリックで音を有効にして BGM を始めます。タブが裏に回ると音を止めます。
- BGM: オルゴール風のメロディ、ぽこぽこしたベース、裏拍の小さなハイハットです。C - Am - F - G の4小節 × 2パターンをループします。危険度に応じてテンポが最大22%上がり、ゲームオーバーでフェードアウトします。
- 効果音:

  | 場面 | 関数 |
  | --- | --- |
  | 手が猫を運んでくる「ぽっ」/ 離す「ぴゅっ」 | `playPick` / `playDrop` |
  | 着地「ぽふっ」（落下速度で音量が変わる） | `playLand`（`Cat.landImpact`） |
  | 4匹揃った「ぴこん！」/ 連鎖のアルペジオ | `playMatch` / `playChain` |
  | 「にゃー！」/ ジャンプ / 得点 | `playMeow` / `playHop` / `playScore` |
  | 危険の「ピッ」（危ないほど間隔が短い） | `playWarn` |
  | ゲームオーバー / 新記録 / ボタン | `playGameOver` / `playRecord` / `playButton` |

- タイトル画面のデモでは効果音を鳴らしません（BGM だけ）。
- iPhone では、マナーモード（消音スイッチ）がオンだと音が鳴りません。Web Audio の仕様です。

スマホ対応・パフォーマンス（`src/main.ts`）:

- 長押しメニュー、ダブルタップ拡大、ピンチ拡大、タップ時のハイライトを止めています。ゲーム画面はスクロールしません（Debug パネルの中だけはスクロールできます）。
- 上の SCORE と下のボタンは、iPhone のノッチやホームバーの分だけ内側に寄せています（`safe-area-inset`）。
- 画面幅が狭い（スマホ）ときは、ゲームの外側の帯もゲームと同じ背景色にしています。
- **スリープ（計算の省略）**: 止まってから `sleepAfter` 秒たった猫は「眠らせ」ます。眠っている猫は物理の計算をせず、動かない壁（逆質量 0）として扱います。眠っている猫どうしは当たり判定をせず、同色判定も前のフレームの結果を使い回します。
  - 起こすとき:
    - 起きている猫が `wakeDepth` 以上めり込んできたとき
    - 体全体が `wakeSpeed` 以上で動いている猫が近づいたとき（その場でぷるぷる揺れているだけでは起こさない）
    - 上に乗った猫が `wakeLoadSpeed` 以上で動いているとき（下の猫）。重みで下の猫が潰れ、山が詰まっていきます。眠らせると山が固まって詰まらなくなり、同色がくっつきにくくなったため
    - 4匹揃ったとき（その猫たち）
    - 猫が容器から出ていったとき（その猫の上と両脇の猫だけ。全員を起こすと計算が一気に増えて重くなるため）
    - Debug でパラメータを変えたとき（全員）
  - 起こしてから 0.4 秒は眠りません。眠っていた猫に上から猫が落ちてきても、起きてから「むにっ」と潰れます（潰れ方はスリープなしと同じ約20%）。
  - 効果（PCのChrome、30〜40匹が積み上がって落ち着いた状態）: 1フレームの処理（物理＋描画）が約10.8ms から約0.15ms になりました。
- **眠っている猫の描画の使い回し**: 眠っている猫は1匹ずつ小さな画像（スプライト）に描いておき、毎フレームはそれを貼るだけにします（`drawSleepingCat`）。起きたら画像を捨てます。
  - 描く順番は、眠っていても起きていても同じ（`world.cats` の順）です。以前は眠っている猫をまとめて1枚の画像にして一番下に描いていました。そのため、猫が眠る・起きるたびに重なった猫どうしの前後が入れ替わり、チラついていました（プレイ中に1秒あたり約13回）。
  - 画像は画面のピクセルにそろえて作り、拡大縮小せずに貼ります。眠っている（画像）と起きている（その場で描く）で、見た目がずれたりぼやけたりしません。
  - `drawCat` は毎回、線の継ぎ目・端・透明度などの描画設定をそろえてから描きます。直前に描いたものの設定が残っていると、画像と画面で見た目が変わるためです。
  - 効果（PCのChrome、手で45匹落とすプレイ）: 1フレームの平均 5.3ms → 約3.0ms、重いフレーム（上位1%）13.6ms → 約10ms、同時に起きている猫の平均 14.7匹 → 7.2匹。
- **表情のちらつき対策**: むぎゅ顔・驚き顔・ふつうの顔は、一度変えたら 0.28 秒は保ちます。山の中で軽く触れたり離れたりするたびに表情がパタパタ変わっていたためです。揃った・にゃー・つままれた、の表情はすぐ切り替えます。
- **ちらつき対策**: キャンバスの大きさは、本当に変わったときだけ設定し直します（設定し直すと中身が消えて一瞬白くなるため。iPhone ではアドレスバーの出入りのたびに resize イベントが来ます）。自動画質調整では、描画解像度を何度も上げ下げしないようにしています。
- **自動画質調整**: 1フレームの処理時間（物理＋描画）の平均が 11ms を超えたら、物理のサブステップ数を1段階ずつ下げます（8→5）。4ms 未満が5秒以上続いたら戻します。一番低い段階でも重い状態が3秒続いたら、描画解像度を一度だけ 1.5x に下げます（戻しません）。処理が追いつかないときは、物理の更新を1フレーム2回までにします。Debug ON の間は止めます。Debug 表示の `work`（処理時間）、`q`（段階）、`sleeping`（眠っている猫の数）で確認できます。
- **安全装置**: 猫の形が壊れた（裏返った・潰れすぎた・数値が破綻した）ときは、その場で元の形に戻します（`Cat.isBroken` / `recoverShape`）。裏返っているあいだは面積保存の拘束を掛けません（掛けると裏返ったまま膨らむため）。
- **出現位置の確認**: `+10` とタイトルのデモの猫は、出現する場所に猫がいたら少し待ってから出します（`spawnClear`）。積み上がった猫の中に重ねて出すと、めり込みで猫が裏返ってしまうためです。

描画（`src/render.ts`）:

- 絵柄は、かわいいイラスト調です。光は上から当たる想定で、毛は「背中＝明るい / お腹＝影」のグラデーションと、背中・おでこのツヤで塗っています。
- 胴体は物理点を通る滑らかな閉曲線で描きます。縞模様・胸元のふわふわの白い毛・前足・後ろ足は輪郭点に付いているので、変形に追従します。
- 顔は、ほっぺのふわ毛付きの輪郭、うるうるの目（虹彩のグラデーション・瞳孔・ハイライト2つ・上まぶた）、頬の赤み、ω口、カーブしたひげで描いています。奥側の目と耳を少し小さくして、ななめ向きに見せています。
- 縞猫には、おでこの「M」、ほっぺの線、縞の尻尾を描いています。尻尾は根元が太く、先が細くなります。
- 三毛猫は、白地に茶と黒のぶちを描いています。ぶちは胴体の輪郭点に固定しているので、変形に追従します。位置と、茶・黒どちらが前に来るかは、猫ごとに少しずつ変わります。頭の左右のぶちと耳、尻尾の縞も茶と黒です。
- 伸縮率が `squishFace` を超えると「><」の、むぎゅ顔になります。落下中は目が丸くなり、つままれている間は脱力した「－ －」顔になります。
- 手は横から見た「つまみ」の形です。人差し指（背中側）と親指（顔側）の指先で、首の皮をはさみます。爪と関節で、どの指かわかるようにしています。中指〜小指は握って奥にしまっています。手の向きはつまんだ猫の向きで左右反転し、指は猫の背中側から回り込みます。重ね順は「袖・手の甲・握った指 → 猫 → 首の皮 → 親指と人差し指」です。絵柄は猫と同じイラスト調です（ニットの袖、リブの袖口、ころんとした手、爪のツヤ、指先の赤み）。色は `src/hand.ts` の `HAND` で変えられます。

## 拡張しやすくしている箇所

- **毛色**: `src/colors.ts` の `CAT_COLORS` に追加・変更します。`id` は同色判定用のキーです。ベース・光・影・縞・白い毛・目・鼻などの色と、柄（`solid` / `tabby` / `calico`）、胸元が白いか（`bib`）、足先が白いか（`whitePaws`）を指定できます。
- **容器**: `src/container.ts` の `ContainerShape` は、壁の線分列・描画用の輪郭・ゲームオーバーライン・落下範囲を持ちます。ボウルや三角フラスコなどは、輪郭を線分列で近似した関数（`createBox` と同じ形）を追加すれば差し替えられます。
- **接触情報**: `World.contactPairs` と `Cat.contacts` に、毎フレームの接触ペアを保持しています（Phase 8の同色判定で使う予定）。

## 現在の課題

- 30匹程度を詰め込むと、山の中でごく小さな振動が残ります（平均 3〜5px/s 程度）。`packedDamping` で抑えていますが、スリープ判定は未実装です。
- 頭どうし・頭と胴の重なり順は、配列順で描いているだけです。押し合ったとき、他の猫の頭が上に描かれることがあります。
- 尻尾は衝突判定を持たない見た目用の要素なので、他の猫に重なります（容器の壁は突き抜けないようにしています）。
- 物理処理は、PCのChromeで30匹 約3.4ms/フレームです（40匹を連続で降らせている最中は、描画込みで約7.5ms）。スマートフォン実機では未計測です（Phase 12で計測・最適化します）。
- 強い衝撃（`+10` を連打するなど）で、点が他の猫のポリゴンを貫通して引っかかる可能性があります。現状では、重大な破綻は観測していません。
- 手が上へ戻っている間（約0.5秒）のタップは無視されます。テンポよく落としたいときに、もどかしいかもしれません。
